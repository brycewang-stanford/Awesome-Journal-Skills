# 《系统工程学报》理论分析（jse-tju-theory-analysis）

## 触发时机

当模型已闭合，需要决定应证明什么、条件和结论是否对应、理论结果如何解释系统机制时使用。
“有公式”不等于理论贡献；本 skill 要求每项形式结果改变对系统边界、互动、反馈或决策规律的理解。
若变量和信息结构仍不完整，先回到 `jse-tju-system-modeling`。

## 输入诊断

收集模型、假设、均衡/最优解定义、候选命题、证明草稿和数值发现。对每个结果先问：

1. 它回答哪条研究问题？
2. 哪些条件是充分、必要或仅为证明便利？
3. 结论是存在、唯一、方向、阈值、稳定、效率还是边界？
4. 该结论相对基准文献新增什么？
5. 用什么反例或数值情景检验适用范围？

若结论只是“目标函数在最优点更优”，删除；若只是算法输出描述，转 `algorithm-computation`。

## 结果层级

| 层级 | 典型交付 | 系统工程价值 |
|---|---|---|
| 可行性 | 解/均衡存在、约束可满足 | 系统设计是否可能 |
| 结构性 | 单调、凸性、分解、阈值 | 解释系统结构如何简化决策 |
| 互动性 | 最优反应、均衡、外部性、福利 | 揭示多主体冲突与协同 |
| 动态性 | 稳定性、收敛域、级联条件 | 解释反馈与长期状态 |
| 比较静态 | 参数变化的方向与区间 | 形成可操作决策规则 |
| 边界性 | 反例、非唯一、失稳、不可行 | 明确理论不适用位置 |

一篇稿件无需覆盖所有层级，但主定理与系统主张必须同层。

## 处理步骤

### 1. 建立“问题—结果—证据”图

每个研究问题只连接必要结果，每个结果连接完整证明或明确计算证据。避免大量引理与主问题无关。
引理应为主定理服务；推论应真正由条件特化获得，而不是换一种语言重复命题。

### 2. 精确陈述

命题前列出模型、参数域、正则条件和比较对象。结论注明量词、方向、严格/非严格、不等式区间和
例外点。不要在证明中临时增加正文未给的条件。

### 3. 设计证明路线

先写证明骨架：关键变换、采用的定理及条件核验、分情况节点、边界处理和结论闭合。正文可给
机制和关键步骤，长代数放附录，但不可用“容易证明”隐藏关键跳步。

### 4. 连接系统机制

每个主结果后解释：哪个系统结构造成该性质；删除该结构是否仍成立；结果如何改变控制、配置、
协同或风险判断。解释必须受定理条件约束，不将局部结果外推为普遍规律。

### 5. 做比较静态和稳定性

先确定可比较参数的现实含义与单位，再选择解析导数、格序、隐函数、数值扫描或局部稳定方法。
方向不全局单调时，报告阈值和分区；多均衡时说明选择机制；动态系统区分局部与全局稳定。

### 6. 寻找反例与边界

主动搜索零交互、极端容量、完全/无信息、高低网络密度、参数等值和初值边界。一个有效反例能
暴露缺失条件，不能把反例悄悄排除。理论不成立处应转化为限制或后续验证情景。

## 命题审计卡

```text
结果编号：
系统问题：
前提条件（逐项）：
结论与量词：
相对基准的新信息：
证明骨架：
关键系统机制：
反例 / 失败边界：
数值或数据验证接口：
可操作含义（限定在条件内）：
```

## 微型示例

弱结果：“信息共享提高系统绩效。”这既无条件，也无比较基准。

合格方向：“当共享精度高于阈值且恢复容量处于给定区间时，分散主体的共享均衡降低期望系统损失；
容量过低时共享诱发同步响应，结论反转。”证明需要给均衡存在、阈值推导和反转条件，数值实验再
展示不同网络结构下阈值如何移动。

## 反模式

- 用公式数量、求导长度或附录页数代替理论新意。
- 定理条件散落在证明中，正文结论无条件化。
- 仅证明算法收敛，就声称解释系统行为。
- 只报局部稳定，却写成全局稳定。
- 比较静态只选一组参数画图，没有解析或范围依据。
- 不报告与直觉相反的边界情形。

## 期刊专属拒稿风险

本刊允许理论研究，但结果需服务系统机制或系统设计。若模型专属性弱、命题是标准凸优化或经典
博弈结论的直接复述，即使证明正确也可能缺乏期刊匹配。近年内容画像只是定位证据，不代表编辑部
规定；动态事实应回查 [`official-source-map.md`](../../resources/official-source-map.md)。

## 输出格式

```text

【定义与均衡/解概念】
【主命题 / 定理 / 推论】
【条件—结论对应表】
【证明骨架与附录分配】
【比较静态 / 稳定性】
【反例与适用边界】
【系统机制解释】
【验证接口】
【最大拒稿风险】
```
