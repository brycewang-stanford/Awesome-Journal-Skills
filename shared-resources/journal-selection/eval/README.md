# Journal-match evaluation

A measurable floor under the "where should I send this paper?" capability.

Until now nothing in this repository could answer *"is the venue recommendation any
good?"* — the matching methodology was asserted, not tested. This directory makes the
**candidate-generation** half of it falsifiable.

| File | What it is |
|---|---|
| [`gold-set.tsv`](gold-set.tsv) | 1,738 `(paper title → true venue)` labels across 232 venues, harvested by [`tools/build_eval_set.py`](../../../tools/build_eval_set.py) from the depth packs' own verified exemplar libraries. Each row carries a `split`: `dev` for tuning, `test` for the reported number. |
| `abstract-terms.tsv` | A term bag per gold paper, resolved against OpenAlex by [`tools/fetch_abstracts.py`](../../../tools/fetch_abstracts.py). Powers the `title+abstract` configuration — the one that resembles what an author actually pastes in. **Not present until a maintainer builds it**: it needs network access, so it is not a CI step, and the eval reports its absence rather than a number from a handful of papers. |
| [`RESULTS.md`](RESULTS.md) | Generated scorecard: recall@{1,5,10,20}, MRR, wrong-lane precision, and a per-discipline breakdown. Regenerated by [`tools/eval_journal_match.py`](../../../tools/eval_journal_match.py). |

## What is and is not measured

[`journal-match.md`](../journal-match.md) is a six-step method. Only **Step 2 —
build the candidate set** — is mechanically checkable, and that is what this measures:
given a paper, does the matcher surface its true venue in the top *k*?

It measures it **through the code the skill runs.** Both this harness and
`tools/match_venues.py` go through `tools/match_lib.py`. Before, the harness
re-implemented its own keyword overlap, so the published number described a retriever
that no author had ever invoked; improving one did not improve the other.

Steps 3–6 (scoring on fit × odds × turnaround × cost × audience, the reach/match/safe
tiering, the resubmission ladder) are model judgement made **after reading each
candidate's skills and `official-source-map.md`**. They are deliberately not scored
here, and a reader should not treat these numbers as a score for the shortlist an
agent actually produces — the harness reads only the scope index.

So: this is a **retrieval floor and a regression test**, not a benchmark of the
capability. Its practical value is that breaking the index now breaks a number.

## The dev / test split

The matcher has four weighting constants. Constants chosen by looking at a number stop
measuring anything, so each gold paper is assigned to `dev` or `test` by a hash of its
title: tuning reads `dev`, and every figure in [`RESULTS.md`](RESULTS.md) is computed on
`test`. `RESULTS.md` prints both halves side by side — a gap between them would mean the
constants had been fitted to noise.

Hashing the title rather than the row position keeps the assignment stable as packs are
added, so a paper never changes sides and releases stay comparable.

## Why abstracts, and why only their terms

The headline query is a bare title, because that is all the exemplar libraries record.
No author picks a journal from a title. `title+abstract` is the realistic configuration.

What is committed is not the abstract: it is the deduplicated, stopword-filtered,
alphabetically sorted set of its content words. That is exactly what retrieval consumes,
it is not readable as prose, and it does not redistribute the publishers' text.
`fetch_abstracts.py` needs the network and is therefore never run by CI — its output is
committed and CI reads the file.

## Why the gold set comes from exemplar libraries

Each depth pack ships `resources/exemplars/library.md` — papers checked against the
publisher's own article pages (with volume, issue and page range) to confirm they
appeared in that venue. That is already a labelled corpus, verified more carefully
than anything we could assemble ad hoc, and it needs no network access to rebuild.

**Its bias, stated plainly:** exemplars are papers the pack authors judged *canonical*
for a venue, so they skew famous and prototypical. Real submission decisions are about
marginal papers, which are harder to route. Read the numbers as an upper bound on
easy cases rather than an estimate of field performance.

## Guarding against leakage

The gold set lives inside the same repository as the index, so leakage is the obvious
objection. Two things keep the headline honest:

1. **Scope terms are never derived from exemplar text.** The index draws on the packs'
   skills, READMEs and the *aims & scope* section of each source map — never
   `exemplars/library.md`, which is the label source. This holds even though the scope
   text was widened to cover every skill in a pack rather than only the four "fit"
   skills.
2. **The headline query is the paper title alone** — words chosen by the paper's
   authors, not by a pack author. The `title+context` configuration adds the
   exemplar gloss and is reported *only* as a contrast, labelled as
   vocabulary-correlated.
3. **`title+abstract` uses text from OpenAlex**, outside this repository entirely.

## Running it

```bash
python3 tools/gen_venue_index.py          # index + scope postings
python3 tools/build_eval_set.py           # gold set
python3 tools/fetch_abstracts.py          # abstract term bags (network; by hand)
python3 tools/eval_journal_match.py --write
```

CI runs `--min-recall-at-10` as a floor on the `test` split, so an index or matcher
regression fails the build rather than silently degrading recommendations.
