# Journal-match evaluation

A measurable floor under the "where should I send this paper?" capability.

Until now nothing in this repository could answer *"is the venue recommendation any
good?"* — the matching methodology was asserted, not tested. This directory makes the
**candidate-generation** half of it falsifiable.

| File | What it is |
|---|---|
| [`gold-set.tsv`](gold-set.tsv) | 1,738 `(paper title → true venue)` labels across 232 venues, harvested by [`tools/build_eval_set.py`](../../../tools/build_eval_set.py) from the depth packs' own verified exemplar libraries. |
| [`RESULTS.md`](RESULTS.md) | Generated scorecard: recall@{1,5,10,20}, MRR, and a per-discipline breakdown. Regenerated by [`tools/eval_journal_match.py`](../../../tools/eval_journal_match.py). |

## What is and is not measured

[`journal-match.md`](../journal-match.md) is a six-step method. Only **Step 2 —
build the candidate set from the index** — is mechanically checkable, and that is
what this measures: given a paper, does `venue-index.tsv` surface its true venue in
the top *k*?

Steps 3–6 (scoring on fit × odds × turnaround × cost × audience, the reach/match/safe
tiering, the resubmission ladder) are model judgement made **after reading each
candidate's skills and `official-source-map.md`**. They are deliberately not scored
here, and a reader should not treat these numbers as a score for the shortlist an
agent actually produces — the harness reads nothing but `scope_keywords`.

So: this is a **retrieval floor and a regression test**, not a benchmark of the
capability. Its practical value is that breaking the index now breaks a number.

## Why the gold set comes from exemplar libraries

Each depth pack ships `resources/exemplars/library.md` — papers checked against the
publisher's own article pages (with volume, issue and page range) to confirm they
appeared in that venue. That is already a labelled corpus, verified more carefully
than anything we could assemble ad hoc, and it needs no network access to rebuild.

**Its bias, stated plainly:** exemplars are papers the pack authors judged *canonical*
for a venue, so they skew famous and prototypical. Real submission decisions are about
marginal papers, which are harder to route. Read the numbers as an upper bound on
easy cases rather than an estimate of field performance.

## Guarding against leakage

The gold set lives inside the same repository as the index, so leakage is the obvious
objection. Two things keep the headline honest:

1. **`scope_keywords` are never derived from exemplar text.** The index draws on skill
   descriptions, fit/topic-selection skills, pack READMEs and the *aims & scope*
   section of each source map — not `exemplars/library.md`.
2. **The headline query is the paper title alone** — words chosen by the paper's
   authors, not by a pack author. The `title+context` configuration adds the
   exemplar gloss and is reported *only* as a contrast, labelled as
   vocabulary-correlated.

## Running it

```bash
python3 tools/gen_venue_index.py          # rebuild the index
python3 tools/build_eval_set.py           # rebuild the gold set
python3 tools/eval_journal_match.py --write
```

CI runs `--min-recall-at-10` as a floor, so an index regression fails the build rather
than silently degrading recommendations.
